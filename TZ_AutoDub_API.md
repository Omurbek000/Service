# Техническое задание
## Проект: Сервис автоматических субтитров и автодубляжа видео (AutoDub/AutoSub API)

Версия документа: 1.0
Дата: 09.08.2026

---

## 1. Общее описание проекта

### 1.1 Назначение
Веб-сервис (REST API + backend-обработка), который принимает от пользователя видеофайл на иностранном языке, автоматически:
1. Определяет язык оригинальной аудиодорожки;
2. Распознаёт речь и получает текст с таймингами;
3. Предлагает пользователю выбрать режим обработки: **субтитры** или **дубляж (переозвучка)**;
4. Выполняет перевод и генерацию результата (файл субтитров или видео с новой аудиодорожкой);
5. Отдаёт готовый результат пользователю.

### 1.2 Цель ТЗ
Описать требования к REST API (Django REST Framework), структуре данных, асинхронной обработке задач, интеграции с ML-компонентами (ASR, перевод, TTS/voice cloning) и нефункциональные требования, достаточные для разработки MVP и последующего масштабирования.

### 1.3 Термины и сокращения
| Термин | Расшифровка |
|---|---|
| ASR | Automatic Speech Recognition — распознавание речи |
| TTS | Text-to-Speech — синтез речи |
| MT | Machine Translation — машинный перевод |
| VAD | Voice Activity Detection — определение речевых сегментов |
| Diarization | Разделение аудио по говорящим (кто когда говорит) |
| Mux/Demux | Объединение/разделение видео- и аудиопотоков |
| Task/Job | Асинхронная фоновая задача обработки |

## 3. Функциональные требования

### 3.1 Загрузка видео
- Поддерживаемые форматы: MP4, MOV, MKV, AVI, WEBM (уточняется на этапе разработки в зависимости от поддержки ffmpeg).
- Максимальный размер файла и максимальная длительность — конфигурируемые параметры (например, 2 ГБ / 60 минут для MVP, лимиты по тарифу).
- Загрузка должна поддерживать:
  - обычную multipart-загрузку для небольших файлов;
  - **chunked/resumable upload** (например, через `django-chunked-upload` или прямую загрузку в S3-совместимое хранилище по presigned URL) для больших файлов.
- После загрузки создаётся объект `Video` и автоматически запускается задача определения языка.

### 3.2 Определение языка и предварительная транскрипция
- Система извлекает аудиодорожку из видео (ffmpeg).
- Прогоняет аудио через ASR-модель (Whisper/faster-whisper/whisperX) для:
  - определения языка с confidence score;
  - получения черновой транскрипции с таймкодами (это можно закешировать и переиспользовать для итогового результата, не гонять ASR дважды).
- Результат (язык + confidence) возвращается пользователю через API/уведомление, предлагается выбор дальнейшего действия.
- Если язык определён с низкой уверенностью — пользователю предлагается подтвердить/выбрать язык вручную из списка.

### 3.3 Выбор режима обработки
Пользователь выбирает один из вариантов (или оба):
- **Субтитры**: генерация файла субтитров (.srt/.vtt) на языке оригинала и/или переведённых на целевой язык; опционально — «вшитые» (hardsub) субтитры прямо в видео или «мягкие» (softsub) как отдельная дорожка.
- **Дубляж**: полная переозвучка на целевой язык с заменой или микшированием аудиодорожки, с сохранением фоновых звуков/музыки (опционально) и с опцией клонирования оригинального голоса диктора.

Пользователь указывает целевой язык (или несколько языков для мультиязычных субтитров).

### 3.4 Обработка — Субтитры
1. Полная транскрипция (если не переиспользуется из п. 3.2) с word-level таймингами.
2. Сегментация на реплики по длине строки/паузам (стандарты субтитров: макс. символов в строке, макс. CPS — символов в секунду).
3. Перевод текста на целевой язык (MT), при необходимости на несколько языков.
4. Генерация файлов `.srt` и `.vtt`.
5. Опционально: наложение субтитров на видео (hardsub) через ffmpeg (`subtitles=` фильтр) с настраиваемым стилем (шрифт, размер, позиция, контур).

### 3.5 Обработка — Дубляж
Ручной выбор диктора/голоса пользователем **не предусмотрен**. Весь процесс подбора голоса — полностью автоматический, на основе анализа оригинальной аудиодорожки.

1. Полная транскрипция с таймингами и **diarization** — определение отдельных говорящих и границ их реплик (pyannote.audio или аналог).
2. **Автоматическое определение пола каждого говорящего** (см. п. 3.5.1) — выполняется один раз на спикера, результат применяется ко всем его репликам.
3. Перевод текста на целевой язык с учётом контекста реплик.
4. Разделение вокала и фоновой дорожки (опционально, отдельная фича) — vocal/background separation (например Demucs/Spleeter).
5. Генерация речи (TTS) на целевом языке для каждой реплики, голос подбирается автоматически:
   - **Приоритетный режим — voice cloning**: голос клонируется из образца оригинальной речи данного спикера (zero-shot, например через CosyVoice). Поскольку клонируется реальный голос человека, пол голоса совпадает с оригиналом автоматически, без дополнительной логики.
   - **Резервный режим — автоподбор из пула голосов**: если клонирование отключено конфигурацией, недоступно технически или качество образца недостаточное (шум, слишком короткий сегмент) — система по определённому полу и языку автоматически выбирает подходящий реалистичный преднастроенный голос TTS-движка (без участия пользователя).
6. Синхронизация длительности сгенерированной речи с оригинальными таймингами реплики (time-stretching без искажения тона, либо адаптация текста перевода под длину).
7. Микширование новой речевой дорожки с фоновой (если разделялась) и замена/добавление аудиодорожки в исходное видео (ffmpeg mux).
8. Формирование итогового видеофайла.

### 3.5.1 Автоматическое определение пола говорящего
- Для каждого уникального спикера (по итогам diarization) выполняется классификация пола голоса:
  - базовый метод — анализ основного тона речи (pitch/F0): типичный диапазон мужского голоса ниже, женского — выше;
  - более точный метод — отдельная ML-модель gender-классификации по аудио (например на базе эмбеддингов спикера из diarization-пайплайна), при низкой уверенности pitch-метода используется как основной.
- Результат (`male` / `female`, плюс `confidence`) сохраняется в привязке к `speaker_id` и используется на этапе выбора/клонирования голоса.
- Пользователю эта информация не показывается и не запрашивается — весь процесс скрыт от него, на выходе он получает уже готовое реалистично озвученное видео.

### 3.6 Статусы и уведомления
- Каждая задача (`Job`) проходит через набор статусов (см. раздел 6.2).
- Пользователь может отслеживать статус через:
  - Polling — GET-запрос статуса задачи;
  - WebSocket/SSE (Django Channels) — push-уведомления о смене статуса и прогрессе (%);
  - Email/webhook — опционально, при завершении длительной задачи.

### 3.7 Управление результатами
- Пользователь может скачать итоговые файлы (видео, .srt, .vtt).
- История задач с возможностью повторного скачивания, удаления, повторного запуска с другими параметрами (например, другой целевой язык).
- Хранение результатов ограничено по времени (например, 30 дней) с последующим автоудалением — конфигурируется.

### 3.8 Лимиты и тарификация (если предусмотрено)
> **Отметка: ПОЖЕЛАНИЕ — будем делать позже, не входит в основной объём работ.**

- Лимиты по количеству/длительности видео в месяц в зависимости от плана.
- Учёт расхода ресурсов (минуты обработки ASR/TTS) на пользователя — для биллинга.

## 4. Нефункциональные требования

| Категория | Требование |
|---|---|
| Асинхронность | Вся тяжёлая обработка (ASR, MT, TTS, ffmpeg) выполняется вне HTTP request/response цикла через очередь задач (Celery). Синхронных долгих запросов быть не должно. |
| Масштабируемость | ML-воркеры (GPU) должны масштабироваться независимо от Django API (отдельные Celery worker pools/очереди по типу задачи: `asr`, `translate`, `tts`, `ffmpeg`). |
| Надёжность | Retry-механизм для сбойных задач, идемпотентность повторных запусков, dead-letter очередь для необрабатываемых задач. |
| Хранение файлов | Видео и результаты хранятся в объектном хранилище (S3/MinIO), не в БД и не на диске веб-сервера. |
| Безопасность | JWT/Token-аутентификация, ограничение доступа к чужим файлам (permission per object), валидация типов/размеров загружаемых файлов, защита от небезопасного содержимого (антивирус-сканирование опционально), rate limiting на загрузку. |
| Логирование и мониторинг | Логирование каждого этапа pipeline с task_id для трассировки, интеграция с Sentry/Prometheus/Grafana для мониторинга очередей и ошибок ML-инференса. |
| GPU-ресурсы | Отдельная инфраструктура для GPU-инференса (Whisper, TTS), возможность батчинга задач. |
| Локализация API | Ответы об ошибках и статусах — с поддержкой мультиязычности интерфейса (минимум EN/RU). |
| Тестируемость | Юнит-тесты на сериализаторы/вьюсеты, интеграционные тесты на полный pipeline (с мок-заглушками ML-моделей). |

### 6.2 Статусы задачи (Job.status)
```
created → uploading → language_detection → awaiting_user_choice
→ queued → processing (transcribing → translating → tts/synthesizing → muxing)
→ completed
→ failed
→ cancelled
```

## 7. Спецификация REST API

Базовый префикс: `/api/v1/`
Формат: JSON. Аутентификация: `Authorization: Bearer <JWT>` для всех эндпоинтов кроме auth.

### 7.1 Аутентификация

| Метод | Endpoint | Описание |
|---|---|---|
| POST | `/api/v1/auth/register/` | Регистрация пользователя |
| POST | `/api/v1/auth/login/` | Получение JWT (access/refresh) |
| POST | `/api/v1/auth/refresh/` | Обновление access-токена |
| POST | `/api/v1/auth/logout/` | Инвалидация refresh-токена |
| GET | `/api/v1/auth/me/` | Данные текущего пользователя |

### 7.2 Видео

**POST `/api/v1/videos/`** — загрузка нового видео
- Request: `multipart/form-data`, поле `file`
- Response `201`:
```json
{
  "id": "uuid",
  "status": "uploading",
  "created_at": "2026-08-09T10:00:00Z"
}
```
- Альтернатива для больших файлов: `POST /api/v1/videos/init-upload/` → получение presigned URL для прямой загрузки в S3, затем `POST /api/v1/videos/{id}/confirm-upload/`.

**GET `/api/v1/videos/`** — список видео пользователя (пагинация, фильтры по статусу/дате)

**GET `/api/v1/videos/{id}/`** — детали видео
```json
{
  "id": "uuid",
  "status": "awaiting_user_choice",
  "duration_seconds": 245,
  "detected_language": "en",
  "detected_language_confidence": 0.97,
  "created_at": "...",
  "jobs": []
}
```

**DELETE `/api/v1/videos/{id}/`** — удаление видео и связанных данных

**GET `/api/v1/videos/{id}/preview-transcript/`** — черновая транскрипция (для предпросмотра до выбора режима)

### 7.3 Задачи обработки (Jobs)

**POST `/api/v1/videos/{id}/jobs/`** — создание задачи обработки (выбор режима пользователем)
- Request (выбор голоса не передаётся — подбор мужского/женского голоса и клонирование происходят полностью автоматически на бэкенде):
```json
{
  "mode": "dubbing",
  "target_languages": ["ru"],
  "hardsub": false
}
```
- Response `201`:
```json
{
  "id": "uuid",
  "video_id": "uuid",
  "mode": "dubbing",
  "status": "queued",
  "progress_percent": 0
}
```

**GET `/api/v1/jobs/{id}/`** — статус и детали задачи
```json
{
  "id": "uuid",
  "mode": "dubbing",
  "status": "processing",
  "progress_percent": 62,
  "current_step": "tts_synthesizing",
  "result_files": null,
  "error_message": null
}
```

**GET `/api/v1/jobs/{id}/result/`** — получение ссылок на готовые файлы (доступно при status=completed)
```json
{
  "video_url": "https://.../result_ru.mp4",
  "subtitles": {
    "srt_url": "https://.../subs_ru.srt",
    "vtt_url": "https://.../subs_ru.vtt"
  }
}
```

**POST `/api/v1/jobs/{id}/cancel/`** — отмена задачи (если ещё не завершена)

**POST `/api/v1/jobs/{id}/retry/`** — повторный запуск упавшей задачи

**DELETE `/api/v1/jobs/{id}/`** — удаление задачи и её результатов

**GET `/api/v1/jobs/`** — список всех задач пользователя (фильтры: `status`, `mode`, `video_id`)

### 7.4 Субтитры (детально, если нужно редактирование)

**GET `/api/v1/jobs/{id}/subtitles/`** — получить сегменты субтитров в редактируемом виде
```json
{
  "language": "ru",
  "segments": [
    {"id": 1, "start": 0.0, "end": 2.3, "text": "Привет, как дела?"},
    {"id": 2, "start": 2.5, "end": 5.0, "text": "Сегодня хорошая погода."}
  ]
}
```

**PATCH `/api/v1/jobs/{id}/subtitles/`** — редактирование текста/таймингов вручную перед финальной генерацией

**POST `/api/v1/jobs/{id}/subtitles/regenerate/`** — пересборка файла субтитров/видео после ручного редактирования

### 7.5 Real-time статус (WebSocket)

`ws://.../ws/jobs/{id}/` — подписка на обновления статуса конкретной задачи
Сообщения от сервера:
```json
{"type": "progress", "job_id": "uuid", "status": "processing", "step": "translating", "progress_percent": 45}
```
```json
{"type": "completed", "job_id": "uuid", "result": {"video_url": "..."}}
```
```json
{"type": "failed", "job_id": "uuid", "error": "TTS synthesis timeout"}
```

### 7.6 Служебные эндпоинты

| Метод | Endpoint | Описание |
|---|---|---|
| GET | `/api/v1/languages/` | Список поддерживаемых языков (для ASR/перевода/TTS) |
| GET | `/api/v1/voices/` | Служебный список голосов резервного пула TTS по языкам/полу (только для внутренней логики автоподбора, не для выбора пользователем в UI) |
| GET | `/api/v1/limits/` | Текущие лимиты/остаток квоты пользователя |
| GET | `/api/v1/health/` | Health-check сервиса |

### 7.7 Коды ошибок
| HTTP код | Ситуация |
|---|---|
| 400 | Невалидные параметры запроса |
| 401 | Не авторизован |
| 403 | Нет доступа к ресурсу (чужое видео/задача) |
| 404 | Ресурс не найден |
| 409 | Конфликт статуса (например, попытка отменить уже завершённую задачу) |
| 413 | Превышен максимальный размер файла |
| 422 | Формат файла не поддерживается |
| 429 | Превышен лимит запросов/квота пользователя |
| 500 | Внутренняя ошибка сервера |
| 503 | Сервис обработки временно недоступен (например, ML-воркеры перегружены) |

## 8. Асинхронный pipeline (Celery)

Рекомендуемая цепочка задач (Celery `chain`/`chord`):

```
extract_audio_task(video_id)
    → detect_language_task(video_id)
        → [ожидание выбора пользователя через API] →
    → create_job(video_id, mode, target_languages, ...)
        → transcribe_task(job_id)              # если ещё не закешировано
            → translate_task(job_id)
                → IF mode == subtitles:
                    → generate_subtitles_task(job_id)
                    → IF hardsub: burn_subtitles_task(job_id)
                → IF mode == dubbing:
                    → diarize_task(job_id)                # определение спикеров и границ реплик
                    → detect_gender_task(job_id)           # автоопределение пола по каждому speaker_id
                    → [optional] separate_vocals_task(job_id)
                    → synthesize_tts_task(job_id)          # voice cloning или автоподбор пресета по полу/языку
                    → align_timing_task(job_id)
                    → mux_audio_video_task(job_id)
            → finalize_job_task(job_id)  # обновление статуса, уведомление
```

Рекомендации:
- Разделить Celery-очереди по типу нагрузки: `cpu_queue` (ffmpeg, muxing), `gpu_queue` (ASR, TTS, MT если локальные модели).
- Использовать `task_acks_late` и ограничение `worker_prefetch_multiplier=1` для GPU-задач, чтобы избежать перегрузки видеопамяти.
- На каждом шаге обновлять `Job.progress_percent` и слать событие в WebSocket-группу `job_{id}`.

## 9. Этапы разработки (предлагаемый Roadmap)

**Этап 1 — MVP (субтитры)**
- Django + DRF базовая структура, аутентификация, загрузка видео
- Celery-интеграция, извлечение аудио, Whisper ASR + детект языка
- Перевод текста (API-интеграция, например DeepL/Google)
- Генерация .srt/.vtt, скачивание результата
- Базовый WebSocket-статус

**Этап 2 — Дубляж без клонирования голоса**
- Diarization + автоопределение пола говорящего (pitch-анализ)
- Автоподбор реалистичного пресет-голоса TTS-движка по полу и языку (без участия пользователя)
- Синхронизация тайминга (базовый time-stretch)
- Mux аудио с видео

**Этап 3 — Продвинутый дубляж**
- Voice cloning (CosyVoice) как приоритетный режим — голос автоматически совпадает по полу/тембру с оригиналом
- Более точная ML-модель определения пола (эмбеддинги спикера) вместо базового pitch-анализа
- Разделение вокал/фон, качественный микс для многоголосых видео

**Этап 4 — Продукт** *(ПОЖЕЛАНИЕ — будем делать позже, не входит в основной объём работ)*
- Тарифы, лимиты, биллинг
- Редактор субтитров (ручная правка перед генерацией)
- Личный кабинет, история, аналитика
- Оптимизация инфраструктуры (масштабирование GPU-воркеров, батчинг)
